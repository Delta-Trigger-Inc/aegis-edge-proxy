# AEGIS Edge Proxy — reference preview

Downloadable standalone packaging of the native `aegis-egress-v1` TCP forwarding
engine built for AEGIS Edge. Version **0.1.0-preview.1** is for controlled setup
and connection tests, **not a production-certified sending release**.

The proxy accepts TLS 1.3 client certificates and signed, expiring, session-bound
requests from an authorized Edge, binds its configured local source IPv4 address,
and forwards the original TCP stream to an explicitly allowed destination on
port 25. Postfix on Edge owns SMTP, STARTTLS, MX resolution, DKIM integration,
queues and retries. This server does not connect to Cloud or store messages.

## Download

Use the release archive and its SHA256SUMS from:
https://github.com/Delta-Trigger-Inc/aegis-edge-proxy/releases/tag/v0.1.0-preview.1

```sh
curl -fLO https://github.com/Delta-Trigger-Inc/aegis-edge-proxy/releases/download/v0.1.0-preview.1/aegis-edge-proxy-0.1.0-preview.1.tar.gz
curl -fLO https://github.com/Delta-Trigger-Inc/aegis-edge-proxy/releases/download/v0.1.0-preview.1/SHA256SUMS
sha256sum -c SHA256SUMS
tar -xzf aegis-edge-proxy-0.1.0-preview.1.tar.gz
cd aegis-edge-proxy-0.1.0-preview.1
```

No GitHub account or token is needed. The release is source plus Docker packaging,
not a prebuilt executable or a signed multi-architecture image. The Docker build
needs Internet access to the pinned Python image and Python package repository.
See [INSTALL.md](INSTALL.md) for credential generation, host preparation and testing.

## Preview limits

The extracted forwarding-function bodies are unchanged from revision recorded in
SOURCE.json. This package excludes the private Edge application, its managed
Postfix compiler, customer mappings and all credentials. It adds an explicit
configuration launcher, private pair-bundle generation and constrained Docker
packaging. The launcher limits destination ranges to /24 or narrower for controlled
tests; never substitute a broad Internet range or remove that check for production.

The reference server does not yet implement the complete product requirements for
idle/total-session/byte ceilings, admission limits before TLS worker creation,
credential revocation automation, IPv6 listeners, continuous liveness health checks,
attested multi-architecture releases or certified rollback. Docker limits bound
process memory/thread resources but do not replace protocol-level hardening.
Restrict inbound TCP 5443 to the authorized Edge IP before starting it. There is no
public general-purpose relay mode and no live-send authorization in this package.
Certificates generated by the helper expire after 30 days; replace the private
pair and restart both ends before expiry. This is manual rotation, not revocation.

## Validation

`pytest -q tests` checks framing, session-bound admission, replay rejection,
endpoint/destination restrictions, capacity, drain and bidirectional half-close.
`tests/integration.py` runs the packaged server as a real subprocess with real
TLS 1.3, generated identities, source-bound connection, signed responses, stream
forwarding, replay rejection, wrong-destination and missing-client-certificate
rejection against a container-local TCP receiver. No external recipient is used.

The host configuration and complete Edge/Postfix sending route still require
site-specific commissioning. A successful connection probe is not an SMTP delivery
or inbox-placement result.
